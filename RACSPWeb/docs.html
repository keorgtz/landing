Instalación — Protocolo de Proyecto

RACSP no es una herramienta que uses. Es un protocolo que vive en tu proyecto. Una vez instalado, simplemente abres tus agentes de IA normalmente en la carpeta del proyecto y cada uno se autoconfigura automáticamente.

Filosofía de RACSP
No uses comandos especiales. No necesitas racsp-wrap ni wrappers. Simplemente abre Claude Code, OpenCode, Antigravity o cualquier agente normalmente en la raíz de tu proyecto. Si detectan .racsp/, se autoconfiguran solos con su perfil SDD y empiezan a compartir memoria con los demás agentes.
Prerrequisitos
  • Node.js 18+ — Para compilar el CLI de RACSP (una sola vez)
  • Git 2.30+ — Tu proyecto debe usar Git
  • Proyecto existente — RACSP se instala dentro de tu proyecto
  • Agentes de IA instalados — Claude Code, OpenCode, Gemini, Antigravity, Codex, etc.

Instalación en 3 Pasos

1
Compilar RACSP (Una Sola Vez)
Descarga y compila el CLI de RACSP. Esto solo lo haces una vez por máquina.
bash 
$ git clone https://github.com/keorgtz/RACSP.git
$ cd RACSP/ryou-cli
$ npm install && npm run build && npm link
2
Instalar el Protocolo en tu Proyecto
Ejecuta el setup wizard en la raíz de tu proyecto. Esto crea la carpeta .racsp/ con todo el protocolo: Brain compartido, perfiles SDD por agente, reglas, y memoria.
bash 
$ cd /path/to/tu-proyecto
$ ryou setup

El wizard detecta tu stack (.NET, Node, Python, etc.), crea la estructura .racsp/, y genera los perfiles SDD para cada agente que tengas instalado.

3
Abrir tus Agentes y Trabajar Normalmente
Ahora simplemente abres tus agentes en la carpeta del proyecto. Cada uno detectará .racsp/ y se autoconfigurará automáticamente.
bash 
# Terminal 1 — Abres Claude Code normalmente
$ cd /path/to/tu-proyecto
$ claude

# Terminal 2 — Abres OpenCode normalmente
$ cd /path/to/tu-proyecto
$ opencode

# Terminal 3 — Abres Antigravity normalmente
$ cd /path/to/tu-proyecto
$ antigravity

Cada agente, al iniciar en la carpeta del proyecto:

  1. Detecta la carpeta .racsp/
  2. Lee .racsp/RACSP.md para entender el protocolo
  3. Lee .racsp/agents/<agente>/ para cargar su perfil SDD
  4. Lee .racsp/BRAIN.md para conocer el estado actual
  5. Lee .racsp/AGENTS.md para ver qué hacen los demás
  6. Se autoconfigura con sus modelos por fase SDD
  7. Empieza a compartir memoria automáticamente

Cómo se Autoconfigura Cada Agente

Cuando un agente abre tu proyecto, lee su configuración específica del protocolo:

Claude Code

Lee .racsp/agents/claude/CLAUDE.md y se autoconfigura con:

  • Opus para orquestar y diseñar
  • Sonnet para construir y verificar
  • Haiku para inicializar y archivar
  • Brain sync automático
OpenCode

Lee .racsp/agents/opencode/opencode.json y se autoconfigura con:

  • GLM-5.1 para orquestar y diseñar
  • Kimi K2.6 para construir
  • DeepSeek Flash para explorar
  • DeepSeek V4 Pro para verificar
Gemini CLI

Lee .racsp/agents/gemini/GEMINI.md y se autoconfigura con:

  • Ultra para orquestar y diseñar
  • Pro para construir y verificar
  • Flash para explorar y archivar
  • Ventana de contexto de 1M tokens
Antigravity / Codex / Otros

Cada agente lee su propia configuración en .racsp/agents/<agente>/ y carga:

  • Sus modelos por fase SDD
  • Reglas de Brain sync
  • Contexto compartido del proyecto
  • Convenciones y patrones

Reglas que los Agentes Acatan Automáticamente

Al detectar .racsp/, cada agente sigue estas reglas sin que tú tengas que recordárselas:

1
Leer el Brain Antes de Actuar
Antes de responder a cualquier solicitud, el agente lee .racsp/BRAIN.md, .racsp/AGENTS.md y .racsp/LOCK.md para conocer el estado actual y evitar conflictos.
2
Usar su Perfil SDD Automáticamente
El agente selecciona el modelo correcto según la fase SDD de la tarea. Si le pides arquitectura, usa Opus/GLM. Si le pides un CRUD, usa Sonnet/Kimi. Si le pides explorar, usa Flash.
3
Bloquear Archivos Antes de Editar
Antes de modificar cualquier archivo, el agente se registra en .racsp/LOCK.md. Si otro agente ya lo tiene bloqueado, espera o pide otra tarea.
4
Escribir en el Brain Después de Completar
Al terminar, el agente actualiza .racsp/BRAIN.md, .racsp/AGENTS.md, libera sus locks en .racsp/LOCK.md, y registra su trabajo en .racsp/brain/history/.
5
Nunca Auto-Certificar
El agente no dice "listo" y se va. Su trabajo queda registrado en el Brain como "pendiente de validación". Otro agente (Reviewer) o el pipeline de validación debe aprobarlo.

Orquestación Multi-Agente
  • 10 tipos de agentes especializados con roles definidos
  • Ejecución paralela de builders, reviewers y explorers simultáneamente
  • 9 modos de operación adaptados a la complejidad de cada tarea
  • Enrutamiento por complejidad automático según el alcance del trabajo
Memoria y Persistencia
  • Brain compartido entre todos los agentes y sesiones
  • Auto-snapshots cada 5 minutos durante la ejecución activa
  • Linaje de tareas completo: quién hizo qué, cuándo y por qué
  • Sincronización multi-sesión para trabajo distribuido en el tiempo
Validación Externa
  • La IA nunca auto-certifica — la validación es siempre externa
  • 6 validadores requeridos y opcionales en pipeline
  • Validación por etapas antes, durante y después de la ejecución
  • Git hooks para validación automática pre-commit y post-merge

  • Lazy loading de contexto: solo carga lo que necesita cada agente
  • Perfiles de proveedor para ajustar calidad/costo según el rol
  • Presupuesto de tokens por tarea con límites estrictos
Integración y Adaptadores
  • Adaptador Claude Code para orquestar agentes de Anthropic

  • Modo de recuperación de emergencia para estado corrupto o builds rotos

Meta-Orquestador Ryou

Ryou es el coordinador maestro de RACSP v2.0. No ejecuta código directamente: analiza, descompone y delega cada fase SDD al agente y modelo más adecuado.

1
Análisis de la Solicitud
Ryou recibe la petición del usuario y la analiza con su modelo de orquestación (GLM-5.1 u Opus) para determinar complejidad, alcance y riesgos.
2
Descomposición en Fases SDD
Divide el trabajo en las 8 fases del pipeline: Orchestrator, Init, Explore, Propose, Design, Apply, Verify y Archive.
3
Asignación Inteligente
Para cada fase, Ryou selecciona el agente externo y el modelo específico según el perfil SDD Adaptive activo.
4
Ejecución Paralela Coordinada
Ryou supervisa la ejecución en paralelo, sincronizando el Brain compartido y resolviendo dependencias entre agentes.
5
Validación y Sincronización
Una vez completadas todas las fases, valida los resultados y sincroniza el estado final en el Brain compartido.

Ventaja Clave
Ryou nunca gasta tokens de flagship en tareas mecánicas. Usa GLM-5.1 u Opus solo para orquestar, y delega el 100% de la ejecución a agentes especializados con modelos ajustados por fase.

Delegación Inteligente

El principio central de RACSP v2.0: los modelos flagship y medium razonan y generan sub-tareas ultra-precisas; los modelos flash y lite ejecutan sin alucinar.

Matriz de Capacidades por Tier
Tier Razonar Ejecutar Decidir Uso en RACSP
Flagship Sí Sí Sí Orchestrator, Propose, Design
Medium Limitado Sí Con contexto Apply, Verify
Flash / Lite No Sí No Init, Explore, Archive

Anti-Alucinación por Diseño

Los modelos flash y lite nunca reciben instrucciones ambiguas. Ryou garantiza que cada sub-tarea entregada a un modelo flash incluye:

  • Archivos exactos a modificar (lista explícita)
  • Cambios exactos a realizar (diff o instrucción lineal)
  • Contexto mínimo necesario (sin ruido del proyecto completo)
  • Validación paso a paso (cada cambio verificable)

Flash nunca decide qué archivos modificar, nunca resuelve símbolos por cuenta propia, y nunca infiere requisitos no explícitos.

Brain Compartido v2

En RACSP v2.0, cada agente opera con un contexto filtrado: solo ve lo que necesita. Pero todos escriben en el mismo estado de proyecto unificado, sincronizado en tiempo real.

Contexto Filtrado por Agente

El Brain v2 no envía el proyecto completo a cada agente. En su lugar, construye una ventana de contexto personalizada según la fase y la tarea:

  • Init / Explore: Estructura de directorios, reglas de arquitectura, dependencias clave
  • Propose / Design: Patrones activos, ADRs relevantes, contratos de interfaz
  • Apply: Archivos objetivo, plantillas de código, tests de referencia
  • Verify: Diff generado, reglas de validación, historial de errores similares
  • Archive: Resumen de cambios, métricas de calidad, lecciones aprendidas

El archivo unified-state.json vive en .racsp/brain/ y es la única fuente de verdad del estado del proyecto. Cada agente lee su slice filtrado y escribe sus actualizaciones atómicas.

Sincronización Cruzada cada 30 Segundos

Ryou coordina una sincronización automática del Brain cada 30 segundos durante la ejecución activa:

  • Pull: Cada agente obtiene el estado actualizado antes de iniciar su siguiente paso
  • Merge: Los cambios no conflictivos se integran automáticamente
  • Broadcast: Las actualizaciones críticas (archivos modificados, tests fallidos) se propagan inmediatamente

Detección y Resolución de Conflictos

Estrategia de Resolución
  • Escritura en archivos distintos: Merge automático, sin intervención
  • Escritura en el mismo archivo (diff compatible): Merge automático con validación posterior
  • Escritura en el mismo archivo (diff conflictivo): Ryou pausa ambos agentes, reasigna a un flagship para resolver manualmente
  • Dependencias circulares detectadas: El grafo de tareas se recalcula y se reordena topológicamente
Garantía de Consistencia
Gracias al Brain Compartido v2, múltiples agentes pueden trabajar simultáneamente en el mismo proyecto sin pisarse. El estado unificado, la sincronización periódica y la resolución de conflictos garantizan que el resultado final sea coherente, completo y validado.

Escenario 5: Generación de Documentación en Paralelo

RACSP permite escalar la generación de documentación usando múltiples instancias de modelos rápidos en paralelo.

1
Configurar el Agente
Define un agente optimizado para tareas paralelas de bajo costo. 
{
  "agent": {
    "name": "documentation",
    "config": {
      "provider": "opencode",
      "model_tier": "cheap",
      "parallel": true
    }
  }
}
2
Crear Tareas de Documentación en Paralelo
Crea tres tareas de documentación que se ejecutarán simultáneamente: referencia API, resumen diario y ADR.
$ ryou task create --id DOC-001 --title "API Reference" --type docs
$ ryou task create --id DOC-002 --title "Daily Summary" --type docs
$ ryou task create --id DOC-003 --title "ADR-014 Authentication" --type docs
3
Asignar al Agente Documentation y Ejecutar en Paralelo
Asigna las tres tareas al agente Documentation y ejecútalas en paralelo para maximizar eficiencia.
$ ryou task assign DOC-001 documentation --provider opencode
$ ryou task assign DOC-002 documentation --provider opencode
$ ryou task assign DOC-003 documentation --provider opencode
$ ryou task execute --parallel DOC-001 DOC-002 DOC-003
4
Validar Calidad de Documentación
Ejecuta validadores específicos para documentación: coherencia, completitud y formato Markdown.
$ ryou validate --task DOC-001 --stage semantic-validator
$ ryou validate --task DOC-002 --stage consistency-validator
$ ryou validate --task DOC-003 --stage semantic-validator
5
Automatizar con Git Hooks
Configura un hook post-merge para regenerar documentación automáticamente después de cada merge.
$ ryou hook create post-merge --agent documentation --task-template docs
$ ryou hook enable post-merge

Los tres sistemas —Claude Code, Antigravity CLI y OpenCode— trabajan juntos bajo la orquestación de RACSP. Sistema de Tareas

Las tareas son la unidad atómica de trabajo en RACSP. Cada tarea tiene alcance exacto, salidas definidas y requisitos de validación.

Formato de Tarea YAML
racsp_version: "1.0.0"
task:
  id: "TASK-001"
  type: "atomic"
  title: "Implementar API de Registro"
  outputs:
    files:
      - path: "src/API/Controllers/UsersController.cs"
        action: "create"
    tests:
      - command: "dotnet test"
        expected: "pass"
  constraints:
    max_files: 4
    max_lines_per_file: 150
  dependencies:
    requires: []
    files_write:
      - "src/API/Controllers/UsersController.cs"
  budget:
    model_tier: "standard"
    max_tokens: 8000
    max_time_minutes: 10
Reglas de Tareas
  • Máximo 5 archivos por tarea atómica
  • Máximo 150 líneas por archivo
  • Toda tarea debe tener requisitos de validación
  • Toda tarea debe declarar su grafo de dependencias
  • Toda tarea debe tener presupuesto de ejecución

Validación

La IA nunca auto-certifica su trabajo. Toda finalización debe ser validada externamente por el pipeline de validación.

Validadores Requeridos
  • Compile Validator — Verifica compilación exitosa
  • AST Validator — Validez sintáctica y estructural
  • Semantic Validator — Cumplimiento de patrones y convenciones
Validadores Opcionales
  • Consistency Validator — Cambios no disruptivos
  • Dependency Validator — Sin dependencias circulares
  • Architecture Validator — Límites de capas respetados
Principio Fundamental
La IA NUNCA auto-certifica finalización. La finalización DEBE ser validada externamente. El agente Validator es el guardián — ninguna tarea está completa sin su aprobación.

Compresión Semántica

Reduce el uso de tokens en un 60-80% reemplazando descripciones completas con referencias simbólicas a patrones del registro.

Cómo Funciona

~2000 tokens
Con Compresión
pattern:clean-architecture
~20 tokens
99% reducción
De 2000 tokens a 20 tokens

Snapshots y Reanudación

RACSP crea snapshots automáticos cada 5 minutos. Sobrevive a pérdida de sesión, truncamiento de contexto, cambio de proveedor y reinicio de conversación.

Auto-Snapshots
  • Cada 5 minutos durante ejecución
  • Al completar una tarea
  • Al cambiar de modo
  • Al cambiar de rama Git
Retención
  • 10 snapshots temporales
  • 24 horas de retención
  • Snapshots por rama
  • Compresión 92%
$ ryou snapshot create                    # Crear snapshot manual
